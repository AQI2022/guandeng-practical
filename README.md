# 巡检前的数据时效复核

面向现场运维工程师的最小原型：在执行工单前，检查系统状态是否过期，给出可解释的复核提示，并提供历史回放和工时测算。

**我的判断：优先验证“执行前缺少数据时效复核”这一系统协同问题。** 数据支持状态陈旧与失败相关，但不足以证明失败由网络、缓存或同步机制中的哪一环造成。因此交付的是可回放的提示规则和前瞻试点方案，不是已证明能减少中断的生产系统。

## 1. 看到了什么

只使用题目发放的 `inspection_tasks.csv`。1242 条原始记录包含 **59 条完全重复记录**，按全局唯一 `task_id` 去重后有 **1183 个工单**；其中 **56 个结果缺失**，不将缺失当成成功。其余 **1127 个已知结果中失败 131 个，失败率 11.62%**。

先统一时区，再计算：

```text
数据年龄（分钟） = execute_time - last_telemetry_sync
```

`execute_time` 的 `+08:00` 与同步时间的 `Z` 代表不同表示方式，不能直接减字符串或去掉时区。正确计算后的年龄为 0–65 分钟。

该年龄表示“距手持终端末次成功拉取的时间”，不表示设备测量值本身的采集时间。CSV 没有设备采集时间、设备 ID 或数据版本；即使拉取成功，也不能据此保证返回值来自最新测量。页面、代码和报告按这一数据边界提示，接入真实设备时必须验证设备身份及返回值的采集时间/版本。

已知结果中，数据年龄 **>15 分钟**的 249 单失败 97 单（38.96%），其余 878 单失败 34 单（3.87%）。但这个关系明显因车间而异：

| 车间 | >15 分钟：失败/工单 | ≤15 分钟：失败/工单 |
|---|---:|---:|
| 一号制氢车间 | 41/66 | 6/216 |
| 二号装配车间 | 2/51 | 17/222 |
| 三号动力车间 | 22/57 | 7/212 |
| 四号综合测试区 | 32/75 | 4/228 |

所以不直接对所有车间强制刷新，也不把低电量或高温的直觉当作结论。二号车间是重要反例，需要单独排查。电量数据仅覆盖较低区间，本题不足以推导设备的安全运行标准。

**根问题假设**：派发/执行环节缺少对设备状态时效和现场条件的一致性复核，导致工程师根据可能过期的信息开始作业。需要补充同步失败日志、设备标识、失败原因和复核后结果来证实。其他可能解释包括不同车间的作业类型、班次或网络环境差异；本数据不能排除这些混杂因素。

## 2. 做了什么

1. **一个共享规则模块**：一号、三号、四号车间中，距末次成功拉取 >15 分钟时提示“执行前复核”；二号车间先影子观察，不据此宣称该车间安全。无时区、未来同步时间、缺字段、非法电量等输入返回“数据异常，需人工核对”。规则不读取 `task_status`。
2. **一个本地操作页面**：选择真实历史样本或输入工单，查看数据年龄、触发原因和下一步。工程师应重新拉取状态、核对设备与工单，成功后重新检查；失败则转人工并记录原因。页面不连接设备、不执行真实刷新、不控制停机，也不以“未提示”代表安全。
3. **可复现的回放**：清洗、阈值选择、分车间选择、基线比较、未知标签敏感性、逐工单决策均能运行脚本重新生成。

本次优先做可解释的轻量规则，避免在 7 天小样本上堆叠复杂模型。未实现现场系统接入、真实刷新、权限管理、干预结果持久化；这些是上线前的后续工作。

仅需 Python 3.10+，不需要安装第三方依赖。在仓库根目录执行：


## 4. 如何选择规则，怎样验证

以北京时间的自然日分段，先去重再划分，避免相同工单泄漏到两段：

- 开发期：2026-09-01 至 09-04，共 667 单，638 单有结果，73 单失败。
- 后期回放：2026-09-05 至 09-07，共 516 单，489 单有结果，58 单失败，27 单未知。

开发期比较候选阈值 5、10、15、20、30、45、60 分钟与各车间范围。在假设“被提示且原本会失败的工单中，有 50% 经复核避免失败”的情景下，联合比较阈值与车间组合：对每个车间仅纳入情景净收益为正的提示，再相加比较；提示成本包括未知结果工单，未知结果不给避免失败收益。结果为 15 分钟、一号/三号/四号。这个 50% 是选择规则用的假设，数据没有测量干预有效率。最终主结论仍用冻结规则的后期回放计算。

策略选择对情景假设敏感。相同开发期数据下，有效率为 40%、复核成本 10 分钟时，候选变为一号/四号；有效率 30% 时为一号；有效率 50% 但复核成本 15 分钟时也为一号/四号。这些是敏感性演算，不是实测有效率或新的试点决定。三号车间单独的盈亏平衡有效率约 41.98%；假设有效率 50% 时，单次复核成本临界约 11.91 分钟。总体临界不能替代分车间现场验证。

**诚实边界**：分析中做过全量探索，已观察到车间异质性，因此后期分段是固定规则的探索性时间回放，不能称为完全未见的独立盲测。后期结果没有再用于修改阈值；尚需未来数据验证。14–16 分钟没有观测样本，15 分钟只是可操作的候选阈值，不能称为精确的物理临界点。

后期已知结果的混淆矩阵：

| | 实际失败 | 实际成功 |
|---|---:|---:|
| 提示复核 | 45 | 36 |
| 未提示 | 13 | 395 |

已知结果中提示 81 次，精确率 **45/81 = 55.56%**，覆盖失败 **45/58 = 77.59%**；仍漏掉 13 次失败。还有 **7 个未知结果工单会收到提示**，真实复核工作量按 **88 次**计算。这 7 次不能归为误报或成功。

各策略使用相同回放窗口、相同成本与相同的 50% 假设比较。低电量≤20%、高温≥60°C 只是对照规则，不是厂家安全阈值。

| 策略 | 全部提示（含未知） | 提示中的已知失败 | 已知成功被提示 | 已知失败未提示 | 净分钟情景值* |
|---|---:|---:|---:|---:|---:|
| 不提示 | 0 | 0 | 0 | 58 | 0 |
| 全部提示 | 516 | 58 | 431 | 0 | -2550 |
| 电量≤20% | 344 | 40 | 285 | 18 | -1640 |
| 温度≥60°C | 149 | 20 | 121 | 38 | -590 |
| 所有车间年龄>15分钟 | 111 | 46 | 58 | 12 | 960 |
| **三个车间年龄>15分钟** | **88** | **45** | **36** | **13** | **1145** |

\* 全部提示都计入 10 分钟成本，未知结果不计任何避免失败的收益。所有值都是离线情景测算，**不是实际节省工时**。

## 5. 怎么证明有用

题目给定每次失败损失 90 分钟，每次提示复核耗时 10 分钟。令 `q` 为“被提示且原本会失败的工单中，因复核而避免失败的比例”，则保守测算：

```text
回放净收益（分钟） = 90 × 45 × q − 10 × 88
```

| 假设干预有效率 q | 净收益测算（分钟） |
|---|---:|
| 0% | -880 |
| 25% | 132.5 |
| 50% | 1145（约19.08小时） |
| 75% | 2157.5 |
| 100% | 3170（该口径的理想上界） |

收支平衡点是 **880/(90×45) = 21.73%**。只看已知标签会得到 20%，但那漏算了未知标签的 7 次复核成本，所以主结论采用 21.73%。若复核有效率达不到这个水平，提示反而增加工时。公式假设未提示工单的结果不变、每次复核成本固定、复核不会引入额外故障，均需上线验证。

未知结果可能非随机缺失。如果给 27 个未知工单的结果作最不利/最有利分配，整体精确率可能为 45/88–52/88，即 **51.14%–59.09%**；整体召回率可能为 45/(58+20)–52/(58+7)，即 **57.69%–80.00%**。这只是边界分析，不填造标签，不把未知当成功。

下一步前瞻验证：先影子记录提示，确认数据与人工记录一致；经现场负责人同意后，在试点车间按可比较班次逐步启用提示，保留对照，记录真实复核耗时、复核是否完成、失败原因、执行结果及覆盖行为。主指标为**每100单的实际总损耗分钟（中断+复核）**，同时看提示率、漏报、未知结果率；比较对照后的净工时改善及不确定性。若收益不成立、未知结果仍大量缺失或误提示影响作业，调整/停止提示试点。不能只看“提示量”或“历史召回率”宣布成功。
